# 给 infra 小白的入门导读

这篇文档解释本项目用到的一些"基础设施"基础概念。读代码前先看一遍，
代码里的详细注释会和这里呼应。

---

## 1. 我们到底在写什么？

一个**推理 runtime（运行时）**：把训练好的模型权重加载进内存，然后一个
token 一个 token 地算出下一个 token。你可以把它理解成一个极简版的
"模型执行器"。

- **模型权重**：一大堆浮点数（几十亿个），训练完就固定不变。
- **推理**：给一段输入，反复做"矩阵乘 + 一些激活"，输出下一个词。

我们用 C++ 写执行器（快、能直接控制内存），用 Python 做权重转换和对齐
（生态好、有 PyTorch）。

---

## 2. 几个高频名词

| 名词             | 一句话解释                                       |
|----------------|---------------------------------------------|
| **tensor（张量）** | 多维数组，比如一个 `[896, 896]` 的矩阵。模型权重就是一堆 tensor。 |
| **token**      | 模型处理的最小单位，一个汉字/词片段会被编码成一个整数 id。             |
| **prefill**    | 把输入 prompt 一次性"喂"进模型、填满缓存的阶段。               |
| **decode**     | 之后每次只算一个新 token 的阶段。                        |
| **KV cache**   | decode 时为了避免重复计算而缓存下来的中间结果（见第 6 节）。         |
| **logits**     | 模型最后一层输出的原始分数，对词表中每个词一个数。                   |
| **greedy**     | 贪心采样：永远选分数最高的那个词。                           |

## 3. 内存布局与指针（最重要）

C++ 里数组就是一段连续内存，"指针"是这段内存的起始地址。

```text
内存地址:  0x1000  0x1004  0x1008  0x100C ...
float 值:   1.0     2.0     3.0     4.0
            ^
            指针 p 指向这里；p[2] 就是 3.0
```

- 一个 `float` 占 4 字节，所以相邻元素地址差 4。
- "多维数组"其实还是一维连续内存，我们**约定**怎么把下标映射到偏移。
  比如 `[n_heads][max_seq_len][head_dim]`，访问第 `(h, t, d)` 个元素的偏移是：

  ```text
  offset = h * (max_seq_len * head_dim) + t * head_dim + d
  ```

  这个"下标 → 偏移"的换算叫**索引运算**，代码里到处都是，也是最容易写错
  的地方（所以单测里专门测它）。

**"视图（view）"**：一个结构体，只记录"指针 + 形状"，自己不拥有内存。
好处是零拷贝；代价是你必须保证底层内存比视图活得久。`TensorView` 就是这样。

## 4. 对齐（alignment）是什么、为什么重要

**对齐**指地址是某个数的整数倍。比如"64 字节对齐"就是地址能被 64 整除。

为什么在乎它：

1. **CPU 缓存行（cache line）**：现代 CPU 一次从内存搬 64 字节。数据按
   64B 对齐摆放，读取时不会"跨界"，缓存利用率高。
2. **SIMD / NEON**：向量指令一次处理多个数，很多要求数据对齐才能发挥性能。
3. **mmap**：把文件直接映射进内存时，映射粒度是页（通常 4KB），对齐的
   tensor 边界让映射更干净。

所以我们的权重文件里，每个 tensor 的数据起点都**补齐到 64 的倍数**，
中间用 0 填充。`kAlignment = 64` 就是这个约定。

## 5. 二进制文件格式与"字节序"

我们不直接在运行时解析 safetensors（太复杂），而是先用 Python 把权重
转换成一个自定义的、结构极简的二进制文件 `.tqwen`：

```text
[ 文件头 header ][ tensor 表 ][ 对齐填充 ][ tensor 数据区 ... ]
```

两个必须懂的概念：

- **字节序（endianness）**：一个多字节整数在内存里的存放顺序。
  我们统一用**小端（little-endian）**——低位字节在前。ARM64 / x86 都是小端，
  所以"写出去的字节"和"结构体在内存里的样子"能对上。
- **结构体 padding（填充）**：编译器为了对齐，可能在结构体字段之间偷偷
  插空字节。这会让"内存布局"≠"磁盘布局"，非常危险。所以我们用
  `static_assert(sizeof(...) == 192)` 这种**编译期断言**把大小锁死，
  一旦有人改了字段导致 padding 变化，编译直接报错。

`runtime/tiny_format.h` 就是这个格式的"唯一契约"，Python 导出脚本必须
和它保持一致。

## 6. KV cache 为什么存在

Transformer 的 attention 里，每个新 token 都要和**之前所有** token 交互。
如果每生成一个词都从头重算前面所有词，计算量是平方级爆炸的。

解决办法：把每个历史 token 算出来的 K、V 向量**缓存**起来，下次直接复用。
这就是 KV cache。它的布局是：

```text
K: [n_layers][n_kv_heads][max_seq_len][head_dim]
V: [n_layers][n_kv_heads][max_seq_len][head_dim]
```

我们一次性申请一整块内存（叫 **arena**，竞技场/大块内存），K 和 V 各占一半。
一次分配比每个层各分配一次更简单、也更快。

## 7. RAII 与 profiler

**RAII**（Resource Acquisition Is Initialization）：C++ 的一个惯用法——
把"开始/结束"配对绑定到一个对象的构造/析构上。对象离开作用域自动析构，
所以"结束"一定会被执行，不怕忘记。

我们的计时器就是这么做的：

```cpp
{
  ScopedTimer t(profiler, "layer_0.q_proj");  // 构造 = 开始计时
  linear(...);
}                                              // 离开作用域，析构 = 停止计时
```

你不需要手写"停止计时"，作用域结束自动触发。`steady_clock` 是单调时钟，
不受系统时间被改的影响，适合测耗时。

## 8. 构建系统（CMake / NDK）

- **CMake**：跨平台的构建配置工具。`CMakeLists.txt` 描述"哪些源文件编成
  什么库/可执行"。`cmake -S . -B build` 生成构建文件，`cmake --build build`
  真正编译。
- **NDK（Native Development Kit）**：把 C++ 编译成能在 Android 上跑的
  ARM 二进制的工具链。我们用**交叉编译**——在 Mac/Linux 上编译出手机能
  跑的程序，再用 `adb push` 推到手机上运行。

---

## 9. 为什么要"fail fast"（快速失败）

加载权重文件时，一旦发现问题（魔数不对、大小不符、偏移越界……）我们
**立刻报错退出**，而不是带着错误继续算。因为一个坏权重如果悄悄混进来，
后面算出的结果会"看起来正常但是错的"，这种 bug 极难排查。
所以在边界处严格校验、大声失败，是 infra 代码的好习惯。
